# Project Glossary

This glossary describes the shared MVP vocabulary. See [domain design](./domain-design.md) for responsibilities and [web architecture](./web-architecture.md) for current implementation boundaries.

| Term | Meaning |
|---|---|
| **Test suite** (`TestSuite`) | A named collection of one or more test cases. |
| **Test case** (`TestCase`) | A test definition containing ID, title, prompt, optional variables and one or more expectations. |
| **Prompt** | The instruction sent to the model under test. It may contain placeholders filled using variables. |
| **Variables** | Named values supplied for placeholders in a test prompt. |
| **Reference answer** | The nonblank `options.expected` string belonging to an exact-match or semantic-similarity expectation. Also called a golden reference. |
| **Rubric** | The nonblank `options.rubric` string belonging to one LLM-judge expectation and describing its judgment criteria. |
| **Expectation** | A complete configured check with an ID, name, evaluator type, threshold and its own criteria in options. Multiple expectations can use the same evaluator with independent criteria. |
| **Evaluator** | A Strategy that evaluates an output against an expectation and returns a finite value on 0–1 and feedback. The three strategies are literal exact match, semantic similarity and LLM judge. |
| **Threshold** | The minimum 0–1 score required for an expectation to pass. Exact match fixes it to 1; the runner compares the value with the threshold. |
| **Score** (`EvalScore`) | A recorded evaluation outcome, including its value, scale and feedback. An expectation outcome also identifies the check, its threshold and pass/fail status; an evaluator error is recorded as a failure. |
| **Test result** (`EvalResult`) | The recorded outcome of one test in a run: output or execution error, scores and test pass/fail status. A test passes when execution succeeds and all its expectations pass. |
| **Run** (`EvalRun`) | One execution of a suite, recording its results, start time and provider/model. |
| **Runner** (`EvalRunner`) | The coordinator that generates once per test using the selected model, evaluates expectations sequentially, applies thresholds and records the results in a run. |
| **Report** (`EvalReport`) | An independent snapshot of a completed run, generated by `ReportGenerator`. It lists results, original prompts and failed expectations without aggregation. |
| **Model provider** (`ModelProvider`) | The contract used by the application to obtain a selected `Model`. A model adapter translates generation calls to an external API. |
| **System under test (SUT)** | The selected `Model` whose responses are being tested. |
| **Export** | A JSON representation of a suite, its tests and their related run and result history. Export can occur before the first run and does not require a new run or report. |
| **Health check** | The current `GET /health` operation, which checks server connectivity rather than domain or dependency readiness. |

Historical results retain test IDs, original prompt templates and recorded outcomes; the MVP does not store complete test versions.
